Arisan Rahasia

A private arisan (rotating savings circle) on Tari Ootle: contribute together, the payout order stays sealed, only this round's winner is revealed.

The scene

Ibu Sari runs the neighbourhood (RT) arisan in Jakarta. Every month, 10 members each put in Rp200.000. In the old way, everyone knows whose turn is next — those still waiting get pressured, and whoever just received the pot gets chased for loans.

In Arisan Rahasia the contributions go into a shared vault, and before the first round Ibu Sari seals the whole payout rotation as one SHA-256 commitment per round. The order can never be changed afterwards — but nobody can see it either. Each round, only that round's winner is revealed, after everyone has contributed.

On-chain unit: TARI. In this demo each member contributes 200 TARI per round (the story's Rp200.000), so each round's pot is 2.000 TARI (the story's Rp2.000.000). Demo wallets start with 2.000 TARI — exactly ten rounds of contributions.

      Event log

        Honest limits

        • The admin knows the order. Ibu Sari (the treasurer) generates the rotation and the salts off-chain. The on-chain commitments guarantee she cannot change the order after sealing it — but she does know it. A fully trustless draw is future work.
        • The vault balance is public, as with other Ootle vaults. What stays hidden is the payout order, and each round's winner until their turn arrives.
        • This demo is a simulation. Member "public keys", salts and balances here are demo values computed in your browser; the real template uses account owner Ristretto keys and real TARI buckets, enforced by the Ootle engine (22 engine tests in tests/ cover the same rules on-chain).
